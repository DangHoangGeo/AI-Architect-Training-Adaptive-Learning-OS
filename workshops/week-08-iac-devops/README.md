# Week 08 Workshop — Reusable Bicep Platform

## Purpose
Apply Week 08 learning from **Bicep, IaC, and DevOps Delivery** in a realistic hands-on project.

## Business context
A growing organization wants a production-minded Azure solution that starts small but can evolve. The team needs both architectural clarity and deployable infrastructure.

## Functional requirements
- Reusable modules
- Environment parameters
- Repeatable deployment

## Non-functional requirements
- Idempotent IaC
- Safe defaults
- Clear module ownership

## Required deliverables
- `pm_brief.md`
- `design.md`
- `architecture_decisions.md`
- `threat_model.md`
- `main.bicep`
- `modules/*.bicep`
- `review.md`
- `reflection.md`

## Completion criteria
- Design explains service choices and rejected alternatives.
- Security and cost are explicitly discussed.
- Bicep compiles after real deployment parameters are supplied.
- Review score is recorded in memory.
