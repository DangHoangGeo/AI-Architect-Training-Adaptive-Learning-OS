# Week 07 Workshop — Secure Enterprise API

## Purpose
Apply Week 07 learning from **Security Architecture and Threat Modeling** in a realistic hands-on project.

## Business context
A growing organization wants a production-minded Azure solution that starts small but can evolve. The team needs both architectural clarity and deployable infrastructure.

## Functional requirements
- Protected API boundary
- Secret management
- Threat model

## Non-functional requirements
- Least privilege
- Auditability
- Reduced public exposure

## Required deliverables
- `pm_brief.md`
- `design.md`
- `architecture_decisions.md`
- `threat_model.md`
- `main.bicep`
- `modules/*.bicep`
- `review.md`
- `reflection.md`

## Completion criteria
- Design explains service choices and rejected alternatives.
- Security and cost are explicitly discussed.
- Bicep compiles after real deployment parameters are supplied.
- Review score is recorded in memory.
